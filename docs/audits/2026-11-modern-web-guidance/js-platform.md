# JavaScript platform APIs, PWA, built-in AI, WebMCP, Wasm audit
Guides reviewed: 17 (js/js, js/calculate-event-differentials, js/capture-location-agnostic-data, js/coordinate-global-events, js/sort-high-precision-timestamps, js/support-global-calendar-systems, pwa/install-web-app, pwa/migrate-web-app-origin, built-in-ai/language-detection, built-in-ai/language-model, built-in-ai/prompt-api, built-in-ai/summarizer, built-in-ai/translator, webmcp/webmcp, webmcp/agentic-forms, webmcp/agentic-javascript-tools, wasm/cpp-on-the-web)

Context: `tsconfig.json` has `"lib": ["dom","dom.iterable","ES2022"]`. So `toSorted`/`findLast` (ES2023), `Object.groupBy`/`Map.groupBy`/`Promise.withResolvers` (ES2024) and `AbortSignal.any` are not typed yet, even though as of Nov 2026 all of them are Baseline Widely available. The Low modernization findings below need `"lib"` raised to `"ES2024"` first. Temporal is **Limited availability** (no Safari), so any Temporal recommendation needs the guide's conditional `temporal-polyfill` load. `Intl.DurationFormat` is **Newly available** (2025-03), so it needs a fallback.

## Findings

### [High] Meetings grid works out SGT calendar days with browser-local `Date` getters, so day labels, calendar overlays and exports are a day off outside UTC+0…+8
- Guide: `js/capture-location-agnostic-data`: "A legacy `Date` is a timestamp (an instant), not a calendar date. Storing `"1990-01-01"` as a `Date` forces you to pick *some* instant (typically midnight UTC), and reading it back in a time zone west of UTC yields `"31/12/1989"`." Also "DO NOT use Plain types if you need to represent a specific moment…" / "DO use `Temporal.PlainDate` for full calendar dates".
- Where:
  - `src/modules/meetings/utils/matrix.ts:13-31` (`normalizeDate`: a `Date` input goes through `getFullYear/getMonth/getDate`), `:52-71` (`generateDateRange`, `setDate`), `:137-146` (`slotIndexToDateTime` builds a local `Date`), `:175` (`getHours/getMinutes`), `:245-250` (`formatDateToISO` reads local fields)
  - `src/modules/meetings/components/grid/MeetingMatrixGrid.tsx:72-74` (`isSameDaySGT` actually compares *local* days), `:101`, `:110`, `:172-175`, `:248` (header and cell labels use `formatDateSGT` on local midnights)
  - `src/modules/meetings/components/room/MeetingRoomView.tsx:158-170, 183-193` (top/best-time labels), `:258` (range summary)
  - `src/modules/meetings/functions/slot-range.ts:27` (`${formatDateToISO(date)}T${timeStr}:00+08:00`)
  - `src/modules/meetings/hooks/useGoogleCalendarOverlay.ts:63-71` (`toIsoDateString` reads local getters), `:89-98`, `:275-279` (Google `timeMin/timeMax`)
  - `src/modules/meetings/hooks/useActiveTimetableOverlay.ts:53, 67` (`date.getDay()` on the local-normalized day)
- Problem: polls store date-only values as UTC midnight (`createPoll/index.ts:56-57`, `new Date(\`${input.startDate}T00:00:00Z\`)`), and superjson sends them to the client as `Date`. `normalizeDate(Date)` reads the *browser's* local fields. Example: a poll that starts 12 Oct, viewed in UTC-5, becomes local 11 Oct. The header then prints "Sun 11 Oct", the best-time labels and the selected-range instants (used for the Google/Outlook/.ics export) move back a day, and Google Calendar busy events and timetable classes from 11 Oct block the 12 Oct column. Users at UTC+9 or later (Japan, Korea, Australia) are affected too: a local midnight there falls on the previous SGT day, so `formatDateSGT` prints the day before. Only UTC+0…+8 renders correctly. Exchange students and travellers are a real share of this audience. Slot indices are positional, so stored availability is fine, but what the user *sees* and *exports* is wrong. The server/MCP twin, `src/modules/meetings/functions/slot-time.ts`, is already TZ-safe (pure `YYYY-MM-DD` and `Date.UTC` math, with tests across `process.env.TZ` values). `matrix.ts` has no such tests.
- Fix: treat the poll window as calendar dates, not instants. Convert once with `toIsoDate(poll.startDate)` (UTC day, which matches how the value is stored), then drive `generateDateRange`, `slotIndexToDateTime`, `formatDateToISO`, `getDay`, `isSameDaySGT` and `toIsoDateString` from `YYYY-MM-DD` strings with `addDaysIso`/`weekdayOf`. Simplest is to reuse `toPollGrid`/`pollDays`/`slotStartInstant` from `slot-time.ts`, or build on `TZDate(…, "Asia/Singapore")` from the existing `@date-fns/tz` dependency. Label days with `formatDateSGT(\`${iso}T00:00:00Z\`)`, or better with an Intl formatter that has `timeZone: "UTC"` for date-only values. Compute "today" with `todayIsoSGT()`. Long term this is a `Temporal.PlainDate` (date) plus `Temporal.ZonedDateTime` with `Asia/Singapore` (slot instants), loaded with the guide's polyfill fallback. Add `process.env.TZ` matrix tests (e.g. `America/New_York`, `Asia/Tokyo`, `UTC`) to `matrix.test.ts`, as `slot-time.test.ts:334-350` already does.

### [High] Meeting `.ics` download writes the browser's local wall-clock time under `TZID=Asia/Singapore`
- Guide: `js/coordinate-global-events`: "**DO** use `Temporal.ZonedDateTime` for events that are bound to a specific geographical location (like a meeting in a specific city)." and "**DO NOT** use `Temporal.PlainDateTime` for global events, as it does not carry time zone information".
- Where: `src/common/functions/ical.ts:25-43` (`timezone: "Asia/Singapore"` on both calendar and event, `start`/`end` are plain `Date` instants). It is called in the browser via `src/modules/meetings/functions/meeting-calendar-links.ts:87-120` → `MeetingCalendarExportPopover.tsx:39,112` (`"use client"`).
- Problem: the repo itself documents the library behaviour in `src/modules/timetable/functions/build-ical.ts:40-46`: "ical-generator renders plain Date objects using their *local* wall-clock fields together with the event's TZID". `buildIcal` works around this by building local-field Dates on the (UTC) server. `createIcsFeed` gets *real instants* from `slotRangeToInstants` and runs in the user's browser. So a meeting at 10:00 SGT downloaded in London becomes `DTSTART;TZID=Asia/Singapore:…T020000`, which imports as 02:00 SGT. The Google and Outlook links use `toISOString()` and are correct, so the three export buttons disagree.
- Fix: pass zone-aware values, e.g. `start: new TZDate(start, "Asia/Singapore")` (`TZDate` overrides `getHours()` etc. to return SGT fields), or drop `timezone` from the meeting feed so ical-generator writes UTC `…Z` times. Add a unit test that checks `DTSTART` under `TZ=Europe/London`. (Verify against ical-generator v11's `formatDate`, since `node_modules` was not available in this audit.)

### [Medium] Google Calendar sync hand-rolls `AbortController` + `setTimeout`, so an unmount or user abort is reported as "timed out"
- Guide: `js/js`: "**DO** combine user-initiated cancellation (`AbortController`) with a deadline using `AbortSignal.any([controller.signal, AbortSignal.timeout(ms)])`" and "**DO** check for both `'TimeoutError'` and `'AbortError'` when inspecting `error.name`".
- Where: `src/modules/meetings/hooks/useGoogleCalendarOverlay.ts:245-258` (unmount cleanup aborts), `:266-271` (one-off controller plus timer), `:302`, `:336-349` (every `AbortError` is treated as a timeout), `:358-362`.
- Problem: when the user leaves the meeting room mid-sync, the unmount `abort()` lands in the catch, which shows a "Google Calendar sync timed out (5s)" toast on the next page and calls `setState` after unmount. A second sync started while one is in flight replaces `activeControllerRef` without aborting the earlier request. Timer bookkeeping is spread over three places.
- Fix: `const signal = AbortSignal.any([controller.signal, AbortSignal.timeout(timeoutMs)])`. Abort the previous controller before starting a new one. In `catch`, show the timeout toast only for `err.name === "TimeoutError"` and stay silent for `"AbortError"`. Drop `timeoutIdRef` and the `clearTimeout` calls. Both APIs are Baseline Widely available; the types need `"lib": ["ES2024"]` or a newer DOM lib.

### [Medium] Streamed assistant answers are not announced to assistive tech, and focus is lost when the Stop button goes away
- Guide: `built-in-ai/prompt-api` (same text in `language-model`): "Make the element that receives the output a polite live region that is in the page from page load, and set `aria-busy="true"` on it while a response streams in, so assistive technologies announce the complete response rather than each chunk (WCAG 4.1.3 Status Messages)." and "If the stop button is hidden while it has focus, move focus to the control that started the generation (WCAG 2.4.3 Focus Order)." These rules are written for on-device streaming, but they describe how to render any streamed model output. The general rule "Keep the user informed … **Don't:** Update the UI without visual cues, or without announcing the update to assistive technology users" applies to all streaming AI.
- Where: `src/modules/assistant/message-list.tsx:13-24` (returns `null` when empty, no `aria-live`/`aria-busy`). It is mounted conditionally in `chat-panel.tsx:178-190` and `chat-page.tsx:178-190`. Stop button: `src/modules/assistant/composer.tsx:43-61`.
- Problem: only the "Assistant is typing" `role="status"` (`typing-indicator.tsx:7`) is announced, and only during `submitted`. Screen-reader users get no announcement of the answer itself. When a stream ends or the user presses Stop, the focused Stop `<button>` is replaced by a `disabled` Send button (the input is empty), so focus falls back to `<body>`.
- Fix: render a wrapper that is always present, e.g. `<div aria-live="polite" aria-busy={isStreaming}>`, around the message list in both panels, with the wrapper outside the `hasMessages` conditional. Alternatively, mirror only the final assistant text into a visually hidden live region when `status` returns to `ready`. When `isRunning` flips to false while the Stop button had focus, move focus to the `<textarea>` (keep a ref and call `focus()` in an effect). Model output already goes through `react-markdown` without raw HTML, which satisfies the "never `innerHTML`" rule.

### [Low] Date-only and SGT wall-clock values are built from hand-assembled ISO strings and fixed `+08:00` offsets instead of an IANA zone or Temporal Plain types
- Guide: `js/capture-location-agnostic-data`: "**DO NOT** construct `Date` objects from hand-built ISO strings (such as `` `${date}T00:00:00Z` ``)", "**DO** identify time zones by IANA name (e.g., `America/New_York`) and never by a fixed UTC offset", and "**DO NOT** use `Intl.DateTimeFormat.prototype.formatToParts()` to extract or compare year, month, or day values". Also `js/calculate-event-differentials`: "**DO** combine separate date and time strings with Temporal methods … instead of interpolating an ISO string".
- Where (24 sites): `src/common/functions/term-date-bounds.ts:14,22,26`; `src/modules/meetings/functions/slot-time.ts:9,78,85,190-191,285-291`; `src/modules/meetings/functions/suggest-times.ts:374,377`; `src/modules/meetings/hooks/useGoogleCalendarOverlay.ts:96,117,124,278-279`; `src/modules/meetings/functions/slot-range.ts:27`; `src/common/components/date-range-picker.tsx:47-48`; `src/modules/timetable/components/CurrentTimeIndicator.tsx:15-20` (`+ 8*60`); `src/modules/timetable/functions/build-ical.ts:60` (`+ 8h`) and `:73` (`new Date(Date.UTC(...)).getDay()` uses *local* `getDay` on a UTC midnight, so the weekday is wrong if the server ever runs at a negative offset). String-compared Intl parts: `src/common/functions/format-date-range-sgt.ts:12-18,33-43`; `src/common/functions/format-date-sgt.ts:26-52`.
- Problem: today this works because Singapore has had no DST since 1982 and Vercel runs in UTC. But the same "SGT day" rule is re-implemented about six ways (offset math, `+08:00` literals, `Intl` with `Asia/Singapore`, `TZDate`). The High bugs above come from exactly that drift. The per-call `toLocaleDateString(…, options)` in `formatDateSGT` also creates a new formatter for every heatmap cell `aria-label` (`MeetingMatrixGrid.tsx:248`, days × 56 cells on each render while painting).
- Fix: centralize in one module, e.g. `src/common/functions/sgt.ts`: `const SG_TZ = "Asia/Singapore"`, memoized `Intl.DateTimeFormat` instances, `todayIsoSGT`, `sgtInstant(isoDate, "HH:MM")` built on `TZDate` (already a dependency). Move callers to it. When Temporal is adopted (behind the guide's `typeof Temporal === 'undefined'` → `temporal-polyfill` loader), map `YYYY-MM-DD` to `Temporal.PlainDate`, poll slots to `PlainDate.toZonedDateTime({ timeZone: SG_TZ, plainTime })`, and read `.year/.month/.day` directly instead of comparing `formatDateSGT` strings.

### [Low] Review "time ago" hand-rolls unit suffixes with 30-day months and 365-day years
- Guide: `js/calculate-event-differentials`: "**DO** format durations for user display using `duration.toLocaleString()` or `new Intl.DurationFormat(locale, { style })` … instead of manually interpolating `${duration.years}y ${duration.months}m...`" and "**DO NOT** fall back to `Date` / `.getTime()` arithmetic for the differential itself".
- Where: `src/common/functions/getHumanReadableTimestampDelta.ts:21-39`, used in `src/modules/reviews/components/ReviewItem/ReviewCreatedAt/ReviewCreatedAt.tsx:17`.
- Problem: `"3mo"`/`"5m"` are ambiguous (minutes vs months) and are read literally by screen readers. Months are approximated as 30 days. There is no machine-readable `<time dateTime>`. It also calls `Date.now()` during render in a client component that is SSR'd, so the server and client text can differ.
- Fix: compute with `Temporal.Now.zonedDateTimeISO("Asia/Singapore").since(created, { largestUnit: "year", smallestUnit: "minute" })` and format with `Intl.DurationFormat("en-SG", { style: "narrow" })`, using feature detection and keeping the current function as the fallback. Wrap the text in `<time dateTime={new Date(createdAt).toISOString()}>`. If "ago" phrasing is wanted, `Intl.RelativeTimeFormat` (Widely available) is a lighter option, though the guide does not name it.

### [Low] Copy-then-sort/reverse and reverse-then-find hand-rolls
- Guide: `js/js`: "**DO** use `array.toSorted(compareFn)` instead of `[...array].sort(compareFn)`", "**DO** use `array.toReversed()` instead of `[...array].reverse()`", "**DO** use `array.findLast(predicate)` … instead of `[...array].reverse().find(predicate)`".
- Where (client code with real array receivers): `src/modules/assistant/use-chat-controls.ts:96-98` (`[...chat.messages].reverse().find(...)`, should be `chat.messages.findLast(m => m.role === "user")`); `src/modules/bidding/components/BidTable.tsx:146,148`; `src/modules/timetable/components/BidsTable.tsx:138`; `src/modules/timetable/functions/current-window.ts:39`; `src/modules/meetings/functions/suggest-times.ts:538,552`; `src/modules/reviews/functions/pageDescriptions.ts:24`; `src/common/components/sortable-table.tsx:41`; `src/common/tools/acad-term.ts:86`; `views/shared/components/HistoryTable.tsx:41,42`; `views/timetable/view.tsx:132`. Server: `src/server/api/roadmaps/planSemester/index.ts:50`, `src/server/mcp/tools/feasibility-check.ts:28`, `src/server/mcp/tools/read/plan-semester.ts:56`. Spreads of `Set`/`Map` iterators (e.g. `BidAnalyticsClient.tsx:58-59`, `budget-math.ts:90,101`, `slot-runs.ts:23`) are correct as written, because the guide says not to drop the conversion for non-Array iterables.
- Fix: raise TS `"lib"` to `"ES2024"`, then use `.toSorted()`, `.toReversed()` and `.findLast()`. All are Baseline Widely available.

### [Low] No web app manifest, so the app is not installable
- Guide: `pwa/install-web-app`: "The app being installed must have a web app manifest. Give the manifest a stable `id` so the browser can keep the app's identity separate from its launch URL." Also "Do not show a non-functional install button in browsers that support neither mechanism."
- Where: none exists. There is no `src/app/manifest.ts`/`manifest.webmanifest`, no `public/` directory, and only `src/app/favicon.ico`. `src/app/layout.tsx:29-36` already sets `themeColor`.
- Problem: students return to the timetable, meetings and bidding pages repeatedly, often on phones, but cannot install the app (there is no standalone display and no home-screen icon beyond a bookmark).
- Fix: add `src/app/manifest.ts` (Next.js `MetadataRoute.Manifest`) with `id: "/"`, `name: "AfterClass"`, `short_name`, `start_url: "/"`, `display: "standalone"`, `background_color`/`theme_color` matching the tokens, and 192/512 PNG icons (`src/app/icon.png`, `apple-icon.png`). Optionally add a custom install button that stays `hidden` until `navigator.install` exists or a `beforeinstallprompt` was captured, following the guide's fallback snippet. Web app manifest support is "Limited availability" (Chromium + Safari), which is fine as progressive enhancement. A service worker is not required for installability.

### [Low] Opportunity: expose page-scoped tools to browser agents via WebMCP (`use-webmcp-tool`)
- Guide: `webmcp/agentic-javascript-tools`: "**MANDATORY:** If the app uses React … register tools through that framework's official WebMCP integration … `use-webmcp-tool` | `useWebMCP(options)`: one call per tool". Also `webmcp/agentic-forms`: "The Declarative API is a poor choice … **Custom UI Components** … **Multi-Step Wizards**", and `webmcp/webmcp`: "Register/unregister tools dynamically depending on the current page context."
- Where (candidates): course/professor search (`src/modules/search/components/SearchCmdk/SearchCmdk.tsx:97-111`, readOnly, navigates to `/search?q=`); the timetable page ("add/remove class section", using existing tRPC mutations); the meeting room (`MeetingRoomView.tsx`: "get best times", "mark my availability for a range"); the bidding analytics filters (`BidAnalyticsClient.tsx:76-85`).
- Problem: the server MCP catalog (`src/mcp`, 50 tools with `readOnlyHint`/`destructiveHint` and a confirm gate) needs OAuth and a separate client. Browser agents on afterclass.io itself cannot act on the page the user is looking at. The forms are poor declarative candidates: the search input sits in a dialog that is not mounted, has no `name`, and the poll form uses a custom date-range picker. That makes the imperative hook the right fit.
- Fix: add `use-webmcp-tool` and `webmcp-types` (`tsconfig` `types`). Call `useWebMCP({ name: "search-courses", description, inputSchema, execute, annotations: { readOnlyHint: true } })` in the search provider, plus route-scoped tools in the timetable and meeting pages with `enabled` instead of conditional hooks. Validate input inside `execute`, return `{ error }` payloads instead of throwing, honor `signal` on tRPC calls, return only after the UI updates, and set `consequentialHint: true` on deletes (mirroring `destructiveTools`). WebMCP is Early Preview behind a flag; the hook feature-detects, so other browsers see no effect.

## Done well
- All user-facing date formatting goes through `Intl` with the IANA zone `Asia/Singapore` (`format-date-sgt.ts`). The bidding card uses `TZDate(Date.now(), "Asia/Singapore")` in a server component. The meetings server/MCP slot math (`slot-time.ts`, `suggest-times.ts`) is pure `YYYY-MM-DD`/UTC arithmetic with tests across `process.env.TZ` values.
- Query strings use `URLSearchParams` correctly, including `getAll`/`append` for repeated keys (`BidAnalyticsClient.tsx:77-84`) and `hash.substring(1)` before parsing the hash (`LoginForm.tsx:75`), exactly as `js/js` prescribes. No `split('&')` parsers, `innerHTML = ''`, `document.createEvent` or `String.fromCharCode` decoding.
- `JSON.parse(JSON.stringify())` appears only in `src/server/mcp/audit-log.ts:24`, where JSON normalization is intended. That is the exception `js/js` allows ("DO NOT replace … when callers depend on JSON wire normalization").
- Number formatting uses `Intl.NumberFormat` with `notation: "compact"` (`formatNumberShortScale.ts`) rather than hand-rolled K/M suffixes.
- Assistant chat history is kept device-only in IndexedDB (not `localStorage`, in line with the prompt-api privacy note). Model output is rendered through `react-markdown` with an href allowlist, never `innerHTML`. Storage reads are wrapped in `try/catch`.

## Guides with no applicable code
- `js/sort-high-precision-timestamps`: no sub-millisecond timestamps are parsed or sorted. `createdAt` sorts (`BidsTable.tsx:140`) are millisecond DB timestamps.
- `js/support-global-calendar-systems`: the app is Gregorian/SMU-term only, with no non-Gregorian calendar display.
- `pwa/migrate-web-app-origin`: there is no installed PWA (no manifest) to migrate, despite `new.afterclass.io`/`www` being listed in `layout.tsx:69`. Revisit if a manifest ships on one origin before a move.
- `built-in-ai/prompt-api`, `built-in-ai/language-model`: no on-device AI. The assistant is a server LLM (`/api/chat`). The streaming a11y rules were applied above. A Prompt API path is not recommended: Chrome desktop only, with 16 GB RAM and 22 GB disk requirements.
- `built-in-ai/summarizer`: no usage. Possible opportunity: a "Summarize reviews" button on course/professor pages using `Summarizer` (`type: "key-points"`), created from the click, hidden when `'Summarizer' in self` is false or availability is `unavailable`, with a `downloadprogress` monitor. - `webmcp/agentic-forms`: no form fits the declarative API well (see the WebMCP finding). Login, signup, reset-password and the revoke-agent form are sensitive and should not be tools.
- `webmcp/webmcp`: no WebMCP code yet. The opportunity is covered above.
- `wasm/cpp-on-the-web`: no C/C++ or `.wasm` in the repo.
