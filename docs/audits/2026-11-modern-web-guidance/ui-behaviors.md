## Findings

### [High] Roadmap editor: keyboard users cannot move courses between terms, because the dnd-kit keyboard sensor is overridden
- Guide: `ui-behaviors/drag-and-drop`: "Provide a keyboard-accessible alternative to pointer reordering." Also `ui-behaviors/drag`: "Ensure the draggable element can also be moved or operated using a single pointer without dragging".
- Where: `src/modules/roadmaps/components/RoadmapCourseChip.tsx:139` (`{...listeners}`), then `:144` (a custom `onKeyDown` comes after the spread and replaces dnd-kit's `onKeyDown` activator); `:131` (`touchAction: "none"` on the whole chip); `:140` (`role="button"` wrapper that contains the nested remove `<button>` at `:66-77`). The same override happens in `src/modules/roadmaps/components/CourseSearchSidebar.tsx:65` and `:76`. Sensors are set up in `RoadmapGrid.tsx:200-207`.
- Problem: `useSortable`/`useDraggable` return `listeners = { onPointerDown, onKeyDown }`. The handler written after the spread replaces the KeyboardSensor activator, so Space only calls `preventDefault()` (the comment says "handled by dnd-kit keyboard sensor", but it never reaches dnd-kit). Clicking or pressing Enter on a sidebar chip always adds the course to Y1 T1 (`MyRoadmapsEditor.tsx:339-363`). After that, the only way to move it to another term is a pointer drag. No "Move to…" menu exists, so keyboard and single-pointer users cannot plan any term other than Y1 T1 (WCAG 2.1.1 and 2.5.7). Two smaller issues: `touch-action: none` on the whole chip stops page scrolling when a swipe starts on a chip, and the guide asks for a dedicated handle when an item contains controls.
- Fix: merge the handlers instead of overriding: `onKeyDown={(e) => { if (e.key === "Enter") props.onClick?.(); listeners?.onKeyDown?.(e); }}`, or move the drag `listeners` and `attributes` onto a dedicated `<button>` grip handle (the `GripVertical` icon), with `touch-action: none` on that handle only. Also add a non-drag alternative: a per-chip actions menu (Radix DropdownMenu) with "Move to Year N / Term X", and let sidebar chips open a "Add to…" term picker instead of always using Y1 T1. Announce moves through dnd-kit's `accessibility.announcements` with term names.

### [High] Meeting availability painting has no keyboard path, and it blocks touch scrolling over the whole grid
- Guide: `user-experience/natural-interactions`: "Make every action reachable without a mouse". Also `ui-behaviors/drag-and-drop`: "Scope `touch-action: none` to the handle only: it disables touch scrolling over the element ... but would trap scrolling if applied to the whole item or list."
- Where: `src/modules/meetings/components/grid/MeetingMatrixGrid.tsx:255-283` (paint cells are plain `<div>`s that only have pointer and touch handlers from `useAvailabilityPainter.ts:143-145` / `slot-drag-handlers.ts:14-27`; they have no `tabIndex`, role or key handler); `MeetingMatrixGrid.tsx:143-148` and `:267` (`touch-none` / `touchAction: "none"` on the whole horizontally scrolling grid container in paint mode).
- Problem: in edit mode a keyboard user cannot mark any slot. Only the "autofill from timetable/Google" shortcuts in `MeetingEditPanel` work. In heatmap mode the cells are `<button>`s with Enter/Space, so the gap is only in painting. On phones, the grid has `min-w-[560px]` inside `overflow-x-auto`. With `touch-action: none` on the container, a swipe that starts over the grid can neither scroll the grid sideways (so later days are out of reach) nor scroll the page.
- Fix: render paint cells as `<button type="button" aria-pressed={painted}>` with an `aria-label` that names the day and time, like `MeetingHeatmapCell`. Enter/Space toggles the slot with the current brush. Add roving-tabindex arrow-key navigation (`spatial-navigation`: preventDefault only when a target exists) and Shift+Arrow to extend a range. For touch, keep `touch-action: pan-x pan-y` on the container and start painting only after a long press or from an explicit "Paint" toggle. Alternatively, apply `touch-action: none` only while a paint gesture is active (the `isDragging` branch already exists).

### [High] Review/roadmap reaction picker only works on mouse hover (no tap, no keyboard)
- Guide: `user-experience/natural-interactions`: "Menus and dropdowns may open on hover, but never only on hover: they also open on click, tap, and keyboard activation, stay open while the pointer moves onto them, and close with Esc (WCAG 2.1.1, 1.4.13)."
- Where: `src/common/components/reaction-picker-button.tsx:32-44` (Radix `HoverCard` trigger; its `onClick` calls `preventDefault`/`stopPropagation`); `:50-58` (each emoji's `onClick` sits on an inner `<span>` inside a `TooltipTrigger` `<button>`). Used by `ReviewReactionButton.tsx:15` and `RoadmapReactionButton.tsx:9`.
- Problem: Radix HoverCard ignores touch (`onTouchStart` preventDefault, pointer handlers exclude touch), and its portalled content closes when the trigger blurs. Tapping "React" on a phone does nothing, and keyboard users cannot reach the emojis. Even when the card is open, pressing Enter/Space on an emoji button fires `click` on the `<button>`, not on the inner `<span>` that owns `onClick`, so keyboard activation does nothing. `hover:text-3xl` also changes layout size on hover.
- Fix: replace the HoverCard with a Radix `Popover` (or `DropdownMenu`) opened on click, tap or Enter. Opening on hover as well is fine as an enhancement. Put `onClick={() => onSelect(label)}` and `aria-label={toTitleCase(label)}` on the emoji `<button>` itself. Replace `hover:text-3xl` with a compositor-only `hover:scale-150` wrapped in `motion-safe:`.

### [High] Information users need is only in hover tooltips on non-focusable elements (conflict badges, data disclaimer, disabled-button reasons)
- Guide: `ui-behaviors/interest-triggered-tooltips`: "a hint exposed as a description must only carry content the user can afford to miss ... anything the user needs belongs in a toggletip or inline." Also: "A user expresses interest in the additional information by hovering or focusing on an `<a>` or `<button>` element."
- Where:
  - `src/modules/roadmaps/components/RoadmapConflictBadge.tsx:55-68`: "Dup"/"Exam"/"CU" badges are `<span>`s, and the explanation of the conflict is only in the tooltip.
  - `src/modules/bidding/components/DisclosureDisclaimer.tsx:11-45`: the whole methodology and missing-data explanation sits in a tooltip on a `<span>`.
  - `src/modules/bidding/components/BidTable.tsx:253-264`: the "Seats Taken" definition is a tooltip on a `<span>` nested inside the sort `<button>`.
  - `src/modules/roadmaps/components/RoadmapList.tsx:236-276`: active/public/unlisted icons are `<span aria-label>` (aria-label on a generic span is not exposed) with tooltip-only text.
  - Disabled-button wrappers whose "why disabled" text is tooltip-only: `src/modules/timetable/components/BidDialogForm.tsx:456-458`, `src/modules/roadmaps/components/RoadmapEditorHeader.tsx:96-99`, `src/modules/roadmaps/components/RoadmapList.tsx:169-171`.
  - `src/modules/meetings/components/room/MeetingParticipantList.tsx:50-52` (participant chip `<span>`).
- Problem: Radix Tooltip opens on hover or on focus of the trigger. These triggers cannot take focus, and Radix tooltips never open on touch. Keyboard, touch and screen-reader users never get the conflict reasons, the data caveats or the reason a control is disabled (WCAG 1.3.1, 2.1.1, 1.4.13).
- Fix: for explanatory text, use a toggletip: a `<button type="button" aria-label="Why: duplicate course">` that opens a Radix `Popover` on click, tap and Enter (optionally also on hover), or show the text inline (the conflict list could appear below the year row). For status icons, use `role="img"` with `aria-label`, or visually hidden text. For disabled controls, follow `custom-button-actions` ("use `aria-disabled="true"` so that there is no loss of focus"): keep the button focusable with `aria-disabled`, guard the handler, and attach the tooltip to the button itself. Native `interestfor` + `popover="hint"` is Limited availability, so keep Radix as the implementation.

### [Medium] Every Radix entry/exit animation class is dead code because `tw-animate-css` is not loaded
- Guide: `ui-behaviors/animate-to-from-top-layer`: "Use the `@starting-style` at-rule to define the styles an element should transition *from* when it is first rendered". Also `user-experience/natural-interactions`: "Popovers and dropdowns should visibly open from the control that triggered them".
- Where: `animate-in`/`animate-out`/`fade-in-0`/`zoom-in-95`/`slide-in-from-*` in `src/common/components/tooltip.tsx:53`, `dropdown-menu.tsx:45,230`, `popover.tsx:33`, `hover-card.tsx:41`, `select.tsx:61`, `alert-dialog.tsx:39,57`, `sheet.tsx:39,61-69`; `src/modules/meetings/components/room/MeetingRoomView.tsx:383`; `src/modules/settings/agents/connect-flow.tsx:132`; `src/modules/assistant/quota-alert-bar.tsx:58`. Also `src/modules/assistant/welcome-bubble/welcome-bubble.tsx:90` (`motion-reduce:animate-none` with no animation to cancel), and unused `@keyframes dialog-content-show/hide` in `src/common/styles/radix-dialog.css:19-39`.
- Problem: Tailwind v4 core has no `animate-in`/`fade-*`/`zoom-*`/`slide-*` utilities. `tw-animate-css` was never `@import`ed in `globals.css` (git history shows no CSS import ever), and the package was removed from `package.json` in #580. All menus, selects, popovers, tooltips, sheets (including the mobile sidebar drawer) and alert dialogs therefore appear and disappear instantly, and the sheet's `duration-300/500` does nothing. This is intended motion that silently does not happen. It is not harmful, but it is misleading code, and it hides the fact that no reduced-motion strategy exists for these overlays.
- Fix: either (a) add `@import "tw-animate-css";` to `src/common/styles/globals.css` and prefix the spatial parts with `motion-safe:` (`motion-safe:data-[state=open]:zoom-in-95`, `motion-safe:slide-in-from-*`), keeping fades unconditional; or (b) remove the classes and define small native keyframes keyed on `[data-state=open|closed]` (Radix `Presence` waits for `animationend`, so use keyframe animations rather than transitions). Place transforms only inside `@media (prefers-reduced-motion: no-preference)` and set `transform-origin: var(--radix-popover-content-transform-origin)` so overlays grow from their trigger. Delete the unused `dialog-content-*` keyframes.

### [Medium] Reduced-motion preference is ignored almost everywhere
- Guide: `ui-behaviors/motion`: "Always respect reduced motion preferences." The guide's own example opts a spinner in with `@media (prefers-reduced-motion: no-preference)`. Also `ui-behaviors/drag-and-drop`: "Respect reduced motion. Skip the animations under `prefers-reduced-motion: reduce`."
- Where: only 4 call sites use `motion-safe`/`motion-reduce` (`CourseSearchSidebar.tsx:69`, `RoadmapTermCell.tsx:82`, `RoadmapCourseChip.tsx:46`, `welcome-bubble.tsx:90`). Unguarded motion:
  - `animate-spin` ×31 in 29 files (for example `CalendarExportPopover.tsx`, `MeetingRoomView.tsx:391`, `theme-toggle.tsx:34`)
  - `animate-bounce` in `src/modules/assistant/typing-indicator.tsx:13`
  - `animate-pulse` ×6 (for example `skeleton.tsx`) plus inline infinite `pulse` keyframes in `views/shared/tokens.tsx:61`, `views/shared/components/ViewCard.tsx:22`, `views/timetable/view.tsx:251`, `views/course-search/view.tsx:151`, `views/bid-explorer/view.tsx:490`
  - `hover:scale-110` in `src/common/components/vote-group.tsx:97,123`; `hover:scale-105` on the assistant launcher (`assistant-widget.tsx:58`)
  - dnd-kit sortable `transition` inline styles (`RoadmapCourseChip.tsx:128`)
  - driver.js tours with the default `animate: true` (`src/common/tour/tour.ts:36-45`)
  - smooth scrolling in `src/common/components/scroll-to-top-button.tsx:20-23`, `src/app/(school)/timetable/page.tsx:457`, `src/modules/assistant/chat-page.tsx:200`, `chat-panel.tsx:200`, `use-chat-controls.ts:52`
- Problem: users who ask the OS for reduced motion still get spinning, bouncing, scaling and smooth-scroll animations.
- Fix: use `motion-safe:animate-spin`, `motion-safe:animate-bounce` and `motion-safe:hover:scale-110` (the static icon still communicates "loading"; optionally `motion-reduce:animate-pulse` for an opacity-only cue). Wrap the inline `pulse` keyframes in `views/` in `@media (prefers-reduced-motion: no-preference)`. Add a small `prefersReducedMotion()` helper and pass `behavior: reduce ? "auto" : "smooth"` to `scrollTo`/`scrollIntoView`, `animate: !reduce` to driver.js, and `transition: reduce ? undefined : transition` to dnd-kit. Do NOT add a global `animation-duration: 0.01ms` reset (the guide forbids it).

### [Medium] `ProgressLink` cancels every click, which breaks Cmd/Ctrl/Shift-click and `target="_blank"`
- Guide: `user-experience/natural-interactions`: "Use `<button>` for actions and `<a>` with an `href` for navigation."
- Where: `src/common/components/progress-link.tsx:48-63` (`onClick` always calls `e.preventDefault()` and then `router.push`). It is used in 20 files, including the header home link (`core-layout-header.tsx:22`) and every bidding `ClassCard` (`src/modules/bidding/components/ClassCard.tsx:56`). It is also used with `target="_blank"` in `src/app/account/auth/confirm-account/page.tsx:68`.
- Problem: next/link normally lets modifier clicks through to the browser. This wrapper swallows them, so Cmd/Ctrl-click ("open in new tab") and Shift-click ("new window") navigate the current tab, and `target="_blank"` is ignored. Only `pathname` is used when `href` is an object, so any `query` is silently dropped. A caller's own `onClick` replaces the handler because `{...props}` is spread after it.
- Fix: drop the custom `onClick`. Next 16's `<Link onNavigate={() => progress.start()}>` only fires for same-tab client navigations, so it skips modifier clicks and `_blank`. Read completion with `useLinkStatus()` (or stop the bar in a route-change effect). Minimal patch: `if (e.defaultPrevented || e.button !== 0 || e.metaKey || e.ctrlKey || e.shiftKey || e.altKey || props.target === "_blank") return;`, then pass `props.href` unchanged to `router.push`.

### [Medium] Drag-to-resize and the draggable assistant widget miss pointer-safety and keyboard support
- Guide: `ui-behaviors/drag`: "Start a drag only for the primary pointer button (`event.button === 0`)." Also "Default to `setPointerCapture()` and clear the dragging state on `lostpointercapture`", and "When the handle has focus, move the element with the arrow keys".
- Where:
  - `src/common/components/resize-handle.tsx:14-45` (used in `MeetingRoomView.tsx:333`, `MyRoadmapsEditor.tsx`, `timetable/page.tsx`): any mouse button starts a drag. Listeners are only removed on `pointerup`, so a `pointercancel`/lost capture leaves `pointermove` attached. The `role="separator"` is not focusable, has no `aria-valuenow/min/max`, and has no arrow-key handling.
  - `src/modules/assistant/use-widget-position.ts:160-195` with `assistant-widget.tsx:55-58,93-96`: no button check; no `pointercancel`/`lostpointercapture` reset (`pressStart` can stay set); presses that start on the header's Link/Expand/Close controls still begin a drag after 4px; dragging the launcher may also fire its `onClick` and open the panel on release; no keyboard move.
- Fix: in `onPointerDown`, return early unless `e.button === 0`. Clean up on `lostpointercapture` (this covers `pointerup` and `pointercancel`). Make the separator `tabIndex={0}` with `aria-valuenow`/`aria-valuemin`/`aria-valuemax` and ArrowLeft/ArrowRight handling that calls `onDelta(±16)`. In the widget header, skip `pointerdown` when `e.target.closest("button, a, input")` is not the handle. Track `didDrag` and suppress the launcher click after a real drag. Optionally make the launcher movable with Alt+Arrow keys through the same clamped helper.

### [Low] `useIntersectionObserver` ignores its options and re-subscribes on every render; the scroll-to-top button could be CSS-driven

## Done well
- Native `<details>/<summary>` is used for expandable assistant cards (`src/modules/assistant/expandable-card.tsx:8-22`), the connect flow and the OAuth consent page. This matches `search-hidden-content` and `content-first-noise-reduction`.
- `BidTable`/`BidsTable` put a real `<button>` inside each sortable header and set `aria-sort` only on the active `<th>` (`table-primitives.tsx:24-65`). `BidsTable` keys rows by id, so React moves rows instead of recreating them.
- Copy-to-clipboard is centralized in `use-copy-to-clipboard.ts`, with toast feedback and graceful failure. The MCP views keep an intentional `execCommand` fallback for sandboxed iframes.
- next-themes runs with `disableTransitionOnChange` (`ThemeProvider.tsx:14`), the theme toggle avoids a hydration mismatch, and assistant session actions already handle touch (`session-list.tsx:148` uses `[@media(hover:none)]:opacity-100`).
- Pointer work in the meetings grid uses event delegation and a single shared hover card, and `ResizeObserver` replaces resize listeners in `BidChart.tsx:123-131`. The timetable empty-state CTA focuses with `preventScroll: true` after `scrollIntoView` (`timetable/page.tsx:457-458`).

- anchor-positioning-tab-underline: no tab bars or animated active indicators.

- consistent-cross-document-transitions, cross-document-transitions, directional-navigation-transitions, same-document-transitions, scoped-component-transitions, group-element-transitions: no View Transitions in use. Adding them is optional (e.g. React `<ViewTransition>` for roadmap and timetable list changes), and none of the existing flows require them.
- custom-button-actions, declarative-dialog-popover-control, light-dismiss-a-dialog, platform-controls-dismiss-dialog, prevent-page-scroll-under-modal-dialog, persistent-top-layer-ui: every dialog, sheet and popover is a Radix primitive, which already handles focus trap, Esc, outside-click dismiss and scroll locking (react-remove-scroll). There are no native `<dialog>`/`popover` elements. The only related issue, `aria-disabled`, is covered in the tooltip finding.
- dynamic-sibling-animations, physics-based-easing, parallax-scroll-effects, scrollytelling, scroll-entry-exit-effects, interactive-content-reveal: no stagger, spring, parallax, scroll-driven or spotlight effects.
- dynamic-sort, move-dom-element-without-losing-state: list reorders come from React re-renders of refetched data. The table cases are covered under sortable-table.
- highlight-text-ranges: no search-term highlighting.
- interest-triggered-action-previews: no hover previews of actions.
- scroll-completion-effects: no follow-up effect waits on a programmatic scroll (the timetable focuses immediately with `preventScroll`).
- scroll-target-on-load: no initial scroll-to-item behavior (the timetable grid is not scrolled to "now" on load; that could be a future enhancement).
- spatial-navigation: no custom arrow-key composite widgets apart from Radix/cmdk, which handle their own. The meetings paint grid needs keyboard support first (see the High finding).
- swipe-to-remove, swipe-to-reveal: no swipe gestures.
